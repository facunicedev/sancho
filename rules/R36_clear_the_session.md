# R36. Suggest a fresh session as soon as this one stops helping

> **type:** rule - **status:** active - **default:** yes - **check:** you said it, and only once

Suggest `/clear` **actively**, without waiting to be asked. Four moments:

- **A task was approved.** The moment they close it in words ([R05](R05_approval_to_close.md)).
- **The subject changes.** The next job has nothing to do with the last one. Say it before starting, not halfway through.
- **Research already filed.** Twenty pages were read and what mattered is written in a file. What is left in the window is chaff.
- **Before a long job.** If it will need room, start it with room.

**The condition that is never skipped.** Only suggest it once the state is written down: `HANDOFF.md` current, `Documents/TASKS.md` holding what was decided, material in its folder. Suggesting a fresh session while something lives only in the conversation is asking them to throw work away.

**Why.** A long session is not accumulated memory, it is accumulated noise: discarded drafts, paths that no longer exist, decisions reversed three messages later. All of it competes for attention with what actually matters. This whole repository exists so that clearing costs nothing, because what has to survive lives in files rather than in the window.

**What it is not.** It is not a way to close a task. [R05](R05_approval_to_close.md) still governs: with no explicit yes, a fresh session is not offered as a way of calling something finished.

**How to say it.** One line at the end, naming what is written and where. "That is all in `HANDOFF.md` now. Worth running `/clear` before the next one." Said once, not repeated.
